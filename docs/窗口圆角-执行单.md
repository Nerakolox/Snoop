# 窗口圆角适配系统原生 · 执行单（issue #3）

> 目标：窗口圆角跟随操作系统 —— Windows 10 直角、Windows 11 系统原生圆角、macOS 系统原生圆角。
> 优先用系统原生能力，不引入 CSS 窗口圆角。
> 核准日期：2026-11-06。以下每条现状都已 read / grep / 实机截图核实，不要再自行推断。

---

## 零、已核准的事实

### 0.1 macOS 已经满足，不动

当前 dev 窗口（`target/debug/snoop`）实机截图检查：四角像素 alpha 由 0 渐变到 255，
圆角半径约 10px，是 macOS 原生窗口形状，没有任何 CSS 参与。

原因：窗口是 `titleBarStyle: "Overlay"` 的带标题栏窗口，形状由 NSWindow 负责；
`transparent: true` 只让 webview 背景透明，不影响系统圆角。

**本批 macOS 侧零改动。**

### 0.2 Windows 当前是直角，且是主动关掉的

`src-tauri/src/lib.rs:166-173`：

```rust
// 关系统圆角，避免圆角走 non-client 合成把 halo 也带回来
let pref: DWM_WINDOW_CORNER_PREFERENCE = DWMWCP_DONOTROUND;
```

来源 commit `362e23a`（半透明 vibrancy 那批）。当时为消 halo 一刀切关闭，
没有区分系统版本，结果 Windows 11 上也是直角 —— 与本 issue 诉求相反。

### 0.3 Windows 10 天然直角

`DWMWA_WINDOW_CORNER_PREFERENCE` 最低支持 Windows Build 22000（微软官方文档）。
Windows 10（19045 等）调用该属性无效，窗口保持直角。**不需要为 Win10 写额外逻辑。**

### 0.4 全仓没有窗口级 CSS 圆角

`grep border-radius src` 的结果全部是组件级（按钮、卡片、圆点、滚动条等）。
`.app-shell` / `body` / `#root` 没有 `border-radius`，也没有 `clip-path`。
所以不存在「CSS 圆角与窗口边框/阴影不一致」的现状问题，本批也不引入 CSS 方案。

### 0.5 窗口合成路径

`tauri.conf.json` 主窗口 `transparent: true`，Windows 上是 WebView2 背景透明 + DWM 合成；
圆角与 acrylic 走同一套 DWM 合成，不存在两套形状来源。

## 一、改动清单（只有 1 个文件）

`src-tauri/src/lib.rs`

### 1.1 顶部注释（第 122 行）

**改前：**

```rust
// Windows：关闭原生装饰，改用前端自绘 title bar；圆角/阴影交给系统组合器
```

**改后：**

```rust
// Windows：关闭原生装饰，改用前端自绘 title bar；
// 圆角交给 DWM（Win11 原生圆角，Win10 直角），阴影保持关闭
```

理由：原注释声称「圆角交给系统组合器」，但下面代码实际把圆角关了，注释与行为矛盾。

### 1.2 import（第 127-131 行）

**改前：**

```rust
                use windows::Win32::Graphics::Dwm::{
                    DwmSetWindowAttribute, DWMWA_BORDER_COLOR,
                    DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_DONOTROUND,
                    DWM_WINDOW_CORNER_PREFERENCE,
                };
```

**改后：**

```rust
                use windows::Win32::Graphics::Dwm::{
                    DwmSetWindowAttribute, DWMWA_BORDER_COLOR,
                    DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_DONOTROUND,
                    DWMWCP_ROUND, DWM_WINDOW_CORNER_PREFERENCE,
                };
```

### 1.3 圆角调用（第 166-173 行）

**改前：**

```rust
                            // 关系统圆角，避免圆角走 non-client 合成把 halo 也带回来
                            let pref: DWM_WINDOW_CORNER_PREFERENCE = DWMWCP_DONOTROUND;
                            let _ = DwmSetWindowAttribute(
                                hwnd,
                                DWMWA_WINDOW_CORNER_PREFERENCE,
                                &pref as *const _ as *const _,
                                std::mem::size_of::<DWM_WINDOW_CORNER_PREFERENCE>() as u32,
                            );
```

**改后：**

```rust
                            // 圆角跟随系统：Win11（build >= 22000）用 DWM 原生圆角；
                            // Win10 不支持该属性（最低 build 22000），显式保持直角。
                            // 旧代码为消 halo 一刀切 DONOTROUND，导致 Win11 也是直角（issue #3）。
                            let corner: DWM_WINDOW_CORNER_PREFERENCE =
                                if platform::windows_build_number() >= 22000 {
                                    DWMWCP_ROUND
                                } else {
                                    DWMWCP_DONOTROUND
                                };
                            let _ = DwmSetWindowAttribute(
                                hwnd,
                                DWMWA_WINDOW_CORNER_PREFERENCE,
                                &corner as *const _ as *const _,
                                std::mem::size_of::<DWM_WINDOW_CORNER_PREFERENCE>() as u32,
                            );
```

用 `platform::windows_build_number()`（`RtlGetVersion`，已存在于 `platform/windows.rs:202`），
不要用 `GetVersionExW`。

## 四、已知风险与处理约定

1. **halo 风险**：旧注释记录的 halo 是「开圆角时出现」，但未区分系统版本，也未记录
   是圆角本身、`set_shadow(false)` 还是边框颜色导致。本批先按最小改动打开圆角，
   实测有问题再定位。
2. **Win11 21H2（22000-22522）**：acrylic 走 `SetWindowCompositionAttribute`
   （见 `lib.rs:136-149`），与 DWM 圆角的组合无把握；21H2 已 EOL，圆角不生效则接受，不为它加兼容代码。
3. **若 Win11 实测出现 1px 描边**：不改主逻辑，记录系统 build 号 + 截图后回传，
   再单独决定是否加 `DWMWA_VISIBLE_FRAME_BORDER_THICKNESS = 0`。本批不预先加。
