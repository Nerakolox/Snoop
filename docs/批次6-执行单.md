### 0.5 作息日界 = 4:00（已定，本批最重要的决策）

**背景**：桶归日只看 `bucket_start`（`daily.rs:21-25` 写明是有意为之）。凌晨 1:30 的活动因此属于
**第二天**。若作息也按自然日算，「末次活动」永远停在 23:59、「首次活动」变成 01:20 —— 晚睡在数据上
直接消失，而「这周你比平时晚睡了 40 分钟」正是周报最有价值的那句话。

**决策**：作息模块单独用 4:00 日界。`00:00–04:00` 的活动算前一天的尾巴。

> ⚠️ **这个日界只用于作息模块。** 周报的总时长、7 天条形、分类占比、应用排行**全部仍按自然日**。
> 两套日界绝不能混用——混用会导致「7 天条形加起来 ≠ 周活跃总时长」。Task 1 有一条单测专门钉这个。

某个桶属于哪个作息日，一个表达式搞定（**已实测**）：

```sql
date(datetime(bucket_start/1000, 'unixepoch', 'localtime', '-4 hours'))
```

### 入口


### 分钟数编码（作息模块唯一的编码约定，必须写进注释）

`start_min` / `end_min` / `overnight_end_min` 一律是**距该作息日所属自然日 00:00 的分钟数**：

- 09:12 → `552`
- 次日 01:20 → `1520`（= 1440 + 80）
- 取值范围 `[240, 1680)`，即 04:00 到次日 03:59

SQL 里这么算（`local` = `datetime(bucket_start/1000,'unixepoch','localtime')`）：

```sql
CAST(strftime('%H', local) AS INTEGER) * 60
  + CAST(strftime('%M', local) AS INTEGER)
  + (CASE WHEN date(local) > sleep_day THEN 1440 ELSE 0 END)
```

### 作息规则（逐条实现，全部写进注释）

1. **开工 / 入睡的定义**：作息日内**第一个活跃桶的起点** / **最后一个活跃桶的结束点**
   （`bucket_start + duration_ms`）。
   > 必须用活跃桶，不能用前台桶——否则挂机会把「入睡时间」无限后延。
   入睡因加了 `duration_ms` 而略微越过 04:00 时，**不改判通宵**（通宵判定只看下面的 30 分钟窗口）。

2. **通宵判定**：对每个 4:00 日界（作息日 D 与 D+1 的交界，即 D+1 当天的 04:00），
   若 `[03:30, 04:00)` 内**有**活跃桶 **且** `[04:00, 04:30)` 内**也有**活跃桶 → 判定为跨越日界。

3. **跨界日的处理：D 和 D+1 两天都标 `overnight = true`、都 `counted = false`。**
   > 理由必须写进注释：只标 D 的话，D+1 的「开工」= 通宵的延续（04:0x），会把整周的平均开工时间
   > 往前拽，正是「假均值」本身。D 的入睡未知、D+1 的开工被通宵吞掉，两天都不可信。
   > 代价：D+1 那天正常的入睡时间也被丢掉。这是有意的保守取舍。

4. **一整天连续活跃**（跨了两个 4:00 日界）：按同一规则处理，涉及的 3 个作息日全部 `overnight`、
   全部不进均值。

5. **`overnight_end_min`**：从跨越的那个 04:00 起，沿活跃桶按 `FOCUS_GAP_MS`（5 分钟）断段规则
   往后扫，取该连续段的结束时刻（以 D 所属自然日 00:00 为原点，必然 > 1680）。
   给 UI 渲染「周三 08:52 → 通宵（至次日 05:20）」用。
   D+1 的 `start_min` 置 `None`（开工被通宵吞掉）、`end_min` 照常算，渲染见 Task 5 的
   「（承前）」写法 —— **判据是用户一眼能看出这一格是被合并了，不是漏了**。

6. **活跃下限**：作息日活跃 < `MIN_RHYTHM_ACTIVE_MS`（30 分钟）→ `counted = false`
   （`start_min`/`end_min` 仍如实填，只是不进均值）。**这一天仍计入 `active_ms` 等总时长统计。**

7. **均值分母**：`days_counted` = 本周 `counted == true` 的天数。基线同理，
   **计算前 4 周基线时同样排除通宵日和不足 30 分钟的日子**。

8. **不足 3 天不出模块**：`days_counted < MIN_RHYTHM_DAYS` 时，`avg_start_min`/`avg_end_min` 填 `None`
   （前端据此整块隐藏）。基线侧同理：`baseline_days_counted < MIN_RHYTHM_DAYS` → 基线为 `None`、
   两个 delta 也为 `None`。

9. **措辞**：结构体字段名和注释里一律用**「通宵」**这个中性词。
   **禁止出现「熬夜」「作息紊乱」「不规律」「报复性」**这类评价性表达。

### 应用规则

- `top_apps`：`common::top_apps(&week_buckets, 5)`。
- `new_apps`：本周有活跃、前 4 周（`[week_start-28, week_start-1]`）**完全未出现**的 bundle_id。
  按本周活跃降序，最多 5 条。
- `gone_apps`：**「常用」的判定要写死**——前 4 周累计活跃 ≥ 60 分钟 **且** 出现在 ≥ 2 个不同的周
  （挡掉「装一次试了半小时就卸了」这种一次性应用），且本周活跃 = 0。
  按 `baseline_active_ms` 降序，最多 5 条。60 分钟和 2 周都做成具名常量放 `weekly.rs` 顶部。

### 单测（8 条，`Connection::open_in_memory` + 照抄 `daily.rs:498-548` 的建表/插桶 helper）

1. **两套日界不串味**：`days` 里 7 天的 `active_ms` 之和 == `active_ms`。（本批最重要的一条）
2. **通宵判定**：03:40 和 04:10 各插一个活跃桶 → 相邻两个作息日 `overnight == true` 且
   `counted == false`，`days_counted` 相应减 2。
3. **通宵不污染均值**：一周里 5 天正常 + 1 个通宵日 → `days_counted == 5`，
   均值等于那 5 天的平均（手算断言）。
4. **30 分钟下限**：某天只有 5 分钟活跃 → `counted == false`，但该天的 `active_ms`
   仍出现在 `days` 和周总时长里。
5. **不足 3 天**：只有 2 天可用 → `avg_start_min.is_none()`。
6. **消失的应用**：前 4 周中 2 周各用了 40 分钟（合计 80 分钟 ≥ 60 且 ≥ 2 周）、本周为 0
   → 出现在 `gone_apps`；另造一个「只在 1 周里用了 3 小时」的应用 → **不**出现。
7. **前 4 周无数据**：`baseline` 全 0、`daily_delta_pct == 0.0`，不 panic、不除零。
8. **周界规范化**：传入周三的日期，`week_start` 仍是那周的周一（用 SQLite 反查断言，不依赖机器时区）。

**验收**：`cargo test report::weekly` 全绿；`cargo check` 通过。

### 必须写死的口径

- **按周切分**：从 `week_start_of(month_start)` 起，按周推进到覆盖 `month_end` 为止。
  首尾周会跨出本月 → **裁剪到本月内**（`clip_from`/`clip_to`），`partial = true`。
  > 理由写进注释：不裁剪会把上月/下月的时长算进本月总量；裁剪但不标记，趋势图上一个 2 天的
  > 半截周看起来像「这周崩了」。所以既裁剪、又给前端 `partial` + `days_in_month` 让它如实标注。
- **上下半月**：`1–15` 号 / `16 号–月末`。天数不等（15 vs 13~16）无所谓，比的是**占比**，不是总量。
  两侧任一为 0 活跃 → `half_shift` 返回空 Vec（前端不显示这块）。
- **`min_day`**：只在 `active_ms > 0` 的日子里选。
  > 否则「没开机的那天」永远夺冠，这个数字就没有信息量。
- **`max_day` / `min_day` 的字段名和注释一律中性**，不要出现 `busiest` / `quietest` / `摸鱼` /
  `高产` 这类词。前端文案同理（Task 5）。
- **`new_apps`**：本月有活跃、此前 90 天（`[month_start-90, month_start-1]`）未出现。

### 单测（5 条）

1. **首尾周裁剪**：造一个 1 号是周三的月份，第一周 `days_in_month == 5`、`partial == true`，
   且 `weeks` 各周 `active_ms` 之和 == 月 `active_ms`。
2. **上下半月**：15 号和 16 号各造不同分类的活跃 → `half_shift` 的 `delta_pp` 符号正确。
3. **上月对比**：上月无数据 → `daily_delta_pct == 0.0`，不除零。
4. **`min_day` 跳过零活跃日**：造一个「有前台桶但活跃 0」的日子 → 不被选为 `min_day`。
5. **月末边界**：2 月（含闰年 2028-02）和 31 天的月份，`month_end` 正确。
