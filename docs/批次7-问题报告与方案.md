## 问题一：时间线突变气泡文案重复、信息量为零

### 现状

`src/analytics/constants.ts:207–218`，`SPIKE_QUIP_TEMPLATES` 每个强度档只有 **2 条模板**：

```ts
const SPIKE_QUIP_TEMPLATES = {
  0: ["{H}点忽然有响动，吵到猫了", "{H}点这点动静，谁在敲键盘"],
  1: ["{H}点提速了，摸鱼还摸出节奏了", "{H}点比刚才活跃点，就这"],
  2: ["{H}点这波提速，早干嘛去了", "{H}点突然来劲，撑得住吗"],
  3: ["{H}点键盘没停，是欠了多少活", "{H}点来劲了，deadline 追到门口了"],
  4: ["{H}点手速拉满，命不要了", "{H}点突然爆发，键盘要冒烟了"],
};
```

`pickSpikeQuip` 做纯随机（`Math.random()`），无轮转、无去重。一天内同一强度出现 3 个以上突变点，2 句池必然循环。

**更核心的问题**：文案本身没有新信息。气泡标题已经写了"HH:00 突变"，正文再说"H点突然爆发"只是换个说法重复时刻，用户点开后得不到任何超出气泡外视觉的信息。

### 根因

1. 每档仅 2 句，远低于实际触发频次
2. 选句是随机而非确定性（同一个点反复点击可能看到不同句子）
3. 气泡没有展示数据上下文（是哪个 App、持续多久、比当日均值高多少）

### 方案

**A. 扩充文案池**（最小改动）  
每档扩充到 4–6 句，按"时段"再细分（凌晨 0–6/上午 6–12/下午 12–18/晚上 18–24），避免"下午两点说早干嘛去了"和"凌晨说 deadline 追门口"的语境失真。  
去掉文案里重复小时的措辞（标题已经有时刻），改为描述**行为本身**。  
选句改为 `hash(cellIndex) % pool.length`，保证同一个突变点的文案稳定不变。

**B. 气泡补充数据摘要**（更彻底，信息量有质变）  
在文案行下方加一行数据摘要：
- 持续多久（该格对应的时长）
- 比当日均值高多少（已有 `aggCellLevels` 和 `maxLevel` 可算）
- 当时前台 App 名（从 `buckets` 按时间切片取最多出现的 bundle_id）

气泡宽度从纯文字扩展为「一句话 + 三个数据 chip」，点击才值得。

## 问题二：报告页——内容、结构和页面设计

### 现状

**列表层（`Report.tsx`）**  
`report-row` 仅：类型徽章（日/周/月）+ 日期文字 + 活跃时长 + "›"箭头，四栏平铺。  
- 没有任何相对强弱的视觉信号（哪天特别忙/特别闲一眼看不出）  
- 没有分组（周与日混列，扫一眼不知道自己在看哪周）  
- 当前选中状态只靠 `is-current` 类（一条高亮线），展开时列表被 `ReportSummary` 整块替换，不是原地折叠展开

**详情层（`ReportSummary.tsx`）**  
结构：收起按钮 → 两列网格（左：主数据区，右：海报缩略图 + 操作按钮）

左栏主数据区内容：
```
活跃时长（标签）
大数字
前台 x · 切换 x 次
AI 吐槽段（如果有）
应用 Top 5 | 迷你条（30px 高）+ 对比文字
```

问题：
1. "活跃时长" label 和大数字之间多余，语义冗余——大数字本身就是活跃时长
2. 迷你条（`MiniBars`）30px 高、无刻度、无悬停，几乎没有信息密度
3. 对比文字"近 7 天：活跃 ↑12%·切换 ↓3%"一行带两个方向，视觉噪音
4. AI 吐槽段（`Narrative`）排版和周围的数据信息没有视觉隔离，看起来像正文混在数字里
5. 应用 Top 5 只有图标+名称+百分比，没有时长，也没有相对比较

右栏缩略图：`1000px × scale(0.19) = 190px`，这是个 hack——  
- DOM 实际宽仍是 1000px，overflow hidden + transform，文字在 190px 里不可读  
- 缩略图的白渐变遮住了海报 30% 内容，用意是"示意还有更多"，但效果是信息被截断

**海报本体（`ReportCard.tsx`）**  
海报结构是合理的（头部数据条 → 吐槽 → 各板块），但仅出现在灯箱和导出，作为"应用内快速翻看"用途来说太重。日常翻报告的人想要的是"这天怎么样"的快速答案，不是海报发给别人看。

### 方案

**列表层改造**
- `report-row` 加迷你 sparkline（24 格或 7 格，按 `report_type` 取 `hourly`/`days` 第一项数据——需要 `ReportMeta` 携带简化的 cells，目前后端只给 `active_ms`，需要评估后端改动成本）
- 如果后端不改，退而求其次：把 active_ms 做成相对宽度的细条（在同报型内归一化），让长条/短条的视觉差异替代 sparkline
- 加日期分组标题（本周 / 上周 / 更早）

**详情层改造**
- 去掉"活跃时长"label，直接大数字打头，副标题换成更密的语义行：`前台 3h12m · 切换 124 次 · 输入 18,432 键`
- `MiniBars` 高度从 30px 改到 60px，加极简 Y 轴（仅标最高值）
- 把 AI 吐槽段用引号样式或浅色背景卡片与数据隔开
- 应用 Top 5 加时长，改成 `图标 + 名称 + 时长 + 进度条` 的紧凑行（与海报里的 `ReportAppBars` 相同结构但比例缩小）
- 右栏缩略图换成真正的 CSS `transform-origin: top left` 的精确缩小，去掉白渐变遮罩；或者干脆把右栏改成"快速数字卡片"区（3–4 个关键 stat），把完整海报的入口改成文字按钮"查看完整报告"

## 问题三：设置页——采集·忽略名单交互与样式

### 现状

`Settings.tsx:463–490`：

```tsx
<SettingRow label="忽略名单" desc="列表内的 App 不被记录">
  <div className="setting-ignore-list">   {/* 在 setting-row-right 里 */}
    {settings.ignore_list.map((app) => (
      <span className="setting-ignore-tag">
        {app}
        <button className="setting-ignore-remove"><X size={11} /></button>
      </span>
    ))}
    <div className="setting-ignore-add">   {/* 与 tags 混在同一个 flex-wrap 里 */}
      <input ... />
      <button><Plus /></button>
    </div>
  </div>
</SettingRow>
```

CSS `setting-ignore-list`：`display:flex; flex-wrap:wrap; gap:var(--space-2); max-width:360px`

**问题：**
1. tags 和 input 在同一个 `flex-wrap` 容器里，两者没有视觉分区——名单条目多时 input 会浮到 tags 之间的间隙，很难找
2. `setting-row-right` 有 `flex-shrink:0`，但没有 min-width，名单增长时右侧越来越宽，把左侧 label 压扁
3. `setting-ignore-remove`（X 按钮）可点击区域只有 16×16px，Touch 场景不合格
4. 没有 empty state 提示（名单为空时只有一个裸输入框，不知道它是干什么的）
5. input 没有 `type` 属性（应为 `type="text"`）

### 方案

把忽略名单从 `SettingRow` 的右侧栏改为**独立全宽区块**：

```
┌─ 忽略名单 ────────────────────────────────────────────────────┐
│  列表内的 App 不被记录                           [管理] toggle? │
├───────────────────────────────────────────────────────────────┤
│  [com.apple.finder ×]  [Chrome ×]  [Slack ×]                  │
│  ┌──────────────────────────────────┐  [+]                     │
│  │ App 名或 bundle id               │                           │
│  └──────────────────────────────────┘                          │
└───────────────────────────────────────────────────────────────┘
```

实现方式：
- `SettingRow` 右侧只放计数徽章（`n 个`）
- tags + input 区独立成 `<div className="setting-ignore-body">` 放在 `SettingRow` 下方（参考「未识别按键」现有的降级展示结构，只是那个结构有 padding 问题——见问题四）
- `setting-ignore-remove` hit area 扩到 20×20，加 `title` / `aria-label`

## 问题四：设置页——未识别按键展示区无 padding

### 现状

`Settings.tsx:622–633`：

```tsx
<div className="settings-group">
  <div className="settings-group-title">未识别按键</div>
  <SettingRow label="未识别按键" desc="...">
    ...控制按钮...
  </SettingRow>

  {/* ↓ 直接是 settings-group 的子级，不在 SettingRow 里 */}
  <div className="setting-ignore-list">
    {unmapped.map((u) => (
      <span className="setting-ignore-tag">{u.raw_value} · {u.count}</span>
    ))}
  </div>
</div>
```

`.settings-group` 对任意直接子级没有横向 padding，只有 `SettingRow`（`padding: var(--space-4) var(--space-6)`）和 `settings-group-title` 有内边距。这个裸 `div.setting-ignore-list` 的 tags 顶着容器左边缘渲染，没有左右 padding。

同样，`setting-unmapped-empty` 只有 `margin: var(--space-2) 0 0`（无左边距），文字也顶边。

### 方案（最小改动）

在 `settings.css` 加一条规则：

```css
/* settings-group 内不被 SettingRow 包裹的直接子级（tags 展示区、空态提示）统一左右对齐 */
.settings-group > .setting-ignore-list,
.settings-group > .setting-unmapped-empty {
  padding: 0 var(--space-6) var(--space-4);
}
```

这样不改 JSX，两处同时修复，与 `setting-row` 左右 `var(--space-6)` 对齐。
