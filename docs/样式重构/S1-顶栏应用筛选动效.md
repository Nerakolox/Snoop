## 2. 原型里要复刻的是什么

原型 `snoop-v1-prototype.html` 的相关三段：

**① 芯片脉冲动画（:100-104）**

```css
.chip.flash{animation:flash .7s ease-out}
@keyframes flash{
  0%{transform:scale(1)}
  18%{transform:scale(1.09);box-shadow:0 0 0 5px rgba(107,92,231,.22)}
  100%{transform:scale(1);box-shadow:0 0 0 0 rgba(107,92,231,0)}
}
```

读法：700ms 内，芯片**先快速放大到 1.09 并向外撑开一圈 5px 的半透明紫光环**（在 18% ≈ 126ms
处到达峰值），然后用剩下的 82% 时间缓慢回落到原状、光环收拢消失。是「弹出去 → 慢慢平复」的节奏，
不是对称的呼吸。

**② 触发时机（:352-357）**

```js
function go(patch,{push=true}={}){
  if(push)S.history.push(snap());
  const chg = patch.app!==undefined && patch.app!==S.app;
  Object.assign(S,patch); render();
  if(chg){const c=$('#appchip');c.classList.remove('flash');void c.offsetWidth;c.classList.add('flash')}
}
```

三个关键点，**每一个都要复刻**：

- **触发条件是「app 值真的变了」**，不是「点了芯片」。所以从概览点 App 排行的某一行
  （原型 :486）也会让顶栏芯片闪 —— 这正是这个动效的意义：**告诉用户「你刚才那一点，
  改的是顶栏那个全局筛选」**。
- **切回「全部」也闪**（`patch.app !== S.app` 对 `'all'` 同样成立）。
- **`void c.offsetWidth` 是必需的**。`classList.remove` 紧跟 `add`，浏览器会把两次修改
  合并成「没变化」，动画不会重新播放。中间读一次 `offsetWidth` 强制同步重排，动画才能重启。
  连续快速切换 App 时全靠这一行。

**③ 芯片的悬停与过渡（:92-99）**

```css
.chip{ ... transition:.15s; }
.chip:hover{border-color:var(--purple-dim)}
.chip.active{background:var(--purple-soft);border-color:var(--purple);color:var(--purple)}
```

当前项目的 `.topbar__chip`（`topbar.css:138-156`）**既没有 `transition` 也没有任何 `:hover`
规则**，鼠标划过去毫无反应，是死的。这一并补上。

### 任务 A · 修芯片状态源：让它反映全局 appId（B 的前提，先做）

#### 问题

`src/components/TopBar.tsx:45`：

```tsx
const [selectedApp, setSelectedApp] = useState<{ bundleId: string; name: string } | null>(null);
```

这个本地 state **只在 `pickApp()`（:107-116）里被写入**。而 `:103-105` 的 effect 只做一件事：

```tsx
useEffect(() => {
  if (appId === null) setSelectedApp(null);
}, [appId]);
```

—— 只负责「appId 变成 null 时清空」，**不负责「appId 被外部设成某个值时同步」**。

后果：`src/pages/Overview.tsx:185`、`src/pages/Insights.tsx:165`、`src/pages/Insights.tsx:369`、
`src/pages/Timeline.tsx:404` 都会调 `actions.navigate({ appId: bundleId })` 设置全局筛选。
这些路径下**全局筛选已经生效，但顶栏芯片仍然显示「全部应用」**——状态与显示不一致。

任务 B 的动效挂在 appId 变化上，如果不先修这个，从概览点 App 行时芯片压根不重绘，
动效等于废掉一半场景。

#### 改法：删掉本地 state，改为从 store 的 `appId` 派生

store 只存 `bundleId` 不存展示名，所以需要一个**名字缓存**来补齐展示名。

**A-1** 删除 `TopBar.tsx:45` 这一行：

```tsx
const [selectedApp, setSelectedApp] = useState<{ bundleId: string; name: string } | null>(null);
```

替换为：

```tsx
// store 只存 bundleId，展示名从这里查。来源：应用列表拉取结果 + 用户主动选择。
const [appNames, setAppNames] = useState<Record<string, string>>({});
```

**A-2** 删除 `TopBar.tsx:103-105` 整个 effect：

```tsx
useEffect(() => {
  if (appId === null) setSelectedApp(null);
}, [appId]);
```

（删掉即可，不需要替代品——派生值天然跟随 appId。）

**A-3** 在 `filteredRank` 定义（原 :118-120）**之后**、`useLayoutEffect`（原 :122）**之前**，
新增派生值：

```tsx
// 芯片显示状态完全由全局 appId 派生，不再有本地副本。
// 这样从概览/规律/时间线点 App 下钻（actions.navigate({ appId })）时芯片也会正确更新。
const selectedApp = appId ? { bundleId: appId, name: appNames[appId] ?? appId } : null;
```

> 变量名仍叫 `selectedApp`，**JSX 里 :192-221 那段用到它的代码一个字都不用改。**

**A-4** 改 `pickApp`（原 :107-116），去掉对已删 state 的写入，改为写名字缓存：

### 任务 B · 复刻切换脉冲动效

#### B-1 CSS：在 `src/styles/topbar.css` 的 `.topbar__chip.is-filtered` 规则（约 :152-156）**之后**插入

```css
/* 切换脉冲：App 筛选值发生变化时播一次，把用户视线拉回顶栏，
   告诉他「刚才那一点改的是这里的全局筛选」。复刻自 snoop-v1-prototype.html 的 .chip.flash。
   光环色就近定义在这里，不进 tokens.css——只此一处用。 */
.topbar__chip {
  --chip-flash-ring: rgba(108, 92, 231, 0.22);
}

[data-theme="dark"] .topbar__chip {
  --chip-flash-ring: rgba(139, 124, 240, 0.28);
}

.topbar__chip.is-flash {
  animation: topbar-chip-flash 700ms var(--ease-smooth);
}

/* 18% ≈ 126ms 冲到峰值，剩下 82% 缓慢平复——「弹出去再落回来」，不是对称呼吸 */
@keyframes topbar-chip-flash {
  0%   { transform: scale(1);    box-shadow: 0 0 0 0 var(--chip-flash-ring); }
  18%  { transform: scale(1.09); box-shadow: 0 0 0 5px var(--chip-flash-ring); }
  100% { transform: scale(1);    box-shadow: 0 0 0 0 var(--chip-flash-ring); }
}

@media (prefers-reduced-motion: reduce) {
  .topbar__chip.is-flash { animation: none; }
}
```

几点说明，**照做别改**：

- **0% 与 100% 的 `box-shadow` 都写 `0 0 0 0`**（偏移 0、模糊 0、扩散 0 = 不可见），
  所以只需要一个颜色变量，不用再造一个 alpha 为 0 的版本。
- **两处 `--chip-flash-ring` 是「就近定义的局部自定义属性」**，写在 `.topbar__chip`
  自己身上、由 `[data-theme="dark"]` 覆盖。**不要把它挪进 `tokens.css`。**
- `transform: scale` 不影响布局：`.topbar > *` 是 `flex: none`，芯片放大不会挤动邻居；
  `.topbar` 没有 `overflow` 声明（默认 visible），光环不会被裁掉。**不要为此加 `overflow` 或改 flex。**
- 别给 `.topbar__chip` 加 `position: relative` 或 `overflow: hidden`。芯片是
  `.topbar__app-filter`（`position: relative`）的子元素，下拉弹层是它的兄弟节点，
  动的是芯片不影响弹层定位——**但如果你给芯片加了 transform 以外的定位/裁剪，可能会。**

#### B-2 JS：在 `src/components/TopBar.tsx` 里接上触发

**① 新增 ref**。在 `menuScrollRef`（原 :50）附近加两个：

```tsx
  const chipRef = useRef<HTMLButtonElement>(null);
  const prevAppIdRef = useRef(appId);
```

**② 新增触发 effect**。放在任务 A 删掉的那个 effect 原来的位置（即 `pickApp` 定义之前）：

```tsx
  // App 筛选值真的变了才闪——不是「点了芯片」才闪。
  // 所以从概览/规律/时间线点 App 下钻（actions.navigate({ appId })）同样会触发，
  // 这正是这个动效的用途：把视线拉回顶栏，说明刚才那一点改的是全局筛选。
  // 切回「全部应用」（appId → null）也算变化，同样闪。
  useLayoutEffect(() => {
    if (prevAppIdRef.current === appId) return;   // 首次挂载不闪
    prevAppIdRef.current = appId;
    const el = chipRef.current;
    if (!el) return;
    el.classList.remove("is-flash");
    void el.offsetWidth;   // 强制同步重排：不读这一下，remove→add 会被合并成「没变化」，动画不会重播
    el.classList.add("is-flash");
  }, [appId]);
```

> **为什么是 `useLayoutEffect` 而不是 `useEffect`**：appId 变化时 `is-filtered` 类名也变，
> React 会重写 `className` 属性、抹掉我们手加的 `is-flash`。layout effect 在 React 提交
> DOM 之后、浏览器绘制之前跑，加类和变色同一帧生效，不会先看到「变了色但没动」的一帧。
> `useLayoutEffect` **已经在文件第 1 行 import 了**，不用改 import。

**③ 给芯片挂 ref 和动画结束清理**。改 `TopBar.tsx:186-191` 的按钮开标签：

改前：

```tsx
        <button
          type="button"
          data-tauri-drag-region="false"
          className={`topbar__chip ${selectedApp ? "is-filtered" : ""}`}
          onClick={() => setMenuOpen((v) => !v)}
        >
```

改后：

```tsx
        <button
          ref={chipRef}
          type="button"
          data-tauri-drag-region="false"
          className={`topbar__chip ${selectedApp ? "is-filtered" : ""}`}
          onClick={() => setMenuOpen((v) => !v)}
          onAnimationEnd={(e) => {
            // 只清自己的动画——animationend 会从子元素冒泡上来
            if (e.target === e.currentTarget) {
              e.currentTarget.classList.remove("is-flash");
            }
          }}
        >
```

`e.target === e.currentTarget` 这个判断**不要省**：`animationend` 会冒泡，
芯片里的 `AppIcon` 或将来任何子元素播动画都会误触发清理。

### 任务 C · 补齐芯片的悬停与过渡

`topbar.css:138-150` 的 `.topbar__chip` **没有 `transition`，也没有任何 `:hover` 规则**。
原型里 `.chip{transition:.15s}` + `.chip:hover{border-color:var(--purple-dim)}` 是有反馈的。

**改法**：在 `.topbar__chip` 规则块内（`topbar.css:138-150`），于 `max-width: 220px;` 之后追加：

```css
  transition:
    background var(--dur-fast) var(--ease-smooth),
    border-color var(--dur-fast) var(--ease-smooth),
    color var(--dur-fast) var(--ease-smooth);
```

> ⚠️ **`transition` 里不要带 `transform` 或 `box-shadow`**。那两个属性归 `is-flash` 的
> keyframes 管，同时写 transition 会和动画抢控制权，出现回弹卡顿。

**并在 `.topbar__chip.is-filtered` 规则（约 :152-156）之后、任务 B 新增的那段之前**，插入悬停规则：

```css
.topbar__chip:hover {
  border-color: var(--color-accent);
  color: var(--color-text);
}

/* 已筛选态：底色已是 accent-soft、文字已是 accent，悬停只补一圈边框，
   不改文字色（改了会和未筛选态的悬停混淆） */
.topbar__chip.is-filtered:hover {
  border-color: var(--color-accent);
  color: var(--color-accent);
}
```

**注意规则顺序**：`.topbar__chip:hover` 必须写在 `.topbar__chip.is-filtered` **之后**，
否则筛选态的 `color: var(--color-accent)` 会被后面的 `:hover` 反压。
上面给的插入位置已经保证了这一点，**按位置插就行，别自己挪**。

**commit**：`fix(topbar): 应用芯片补齐悬停反馈与过渡`
