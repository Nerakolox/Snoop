# Snoop · 打包与发布

面向自己的施工手册：怎么出包、怎么上传、怎么让老版本吃到新版。

自更新协议、限速、Mac/Win 差异这些细节直接看代码 `src-tauri/src/updater.rs`，本文只讲操作。

---

## 0. 一次性准备

**Windows：**
- Rust 稳定版（`rustup show` 有 stable-x86_64-pc-windows-msvc）
- Visual Studio Build Tools（含 C++ 桌面开发工作负载）
- Node 18+ 与 `npm ci` 一次
- NSIS 会由 Tauri 首次构建时自动下载到 `%LOCALAPPDATA%/tauri/NSIS`

**macOS：**
- Xcode Command Line Tools（`xcode-select --install`）
- 想同时出 Intel + Apple Silicon 需要 Rust 加两个 target：
  ```bash
  rustup target add x86_64-apple-darwin aarch64-apple-darwin
  ```

**雨云对象存储（一次性）：**
- Bucket 挂在 `https://snoop.cn-nb1.rains3.com`
- 开公开读，禁止列目录
- 至少允许直接 `GET` 到 `/latest.json` 和 installer 文件

## 1. 版本号：一次改全部（用脚本）

发新版第一步，改成同一个语义化版本号。下面这些位置**必须严格一致**，不然自更新会出错乱：

| 文件 | 字段 | 作用 |
|---|---|---|
| `package.json` | `"version"` | npm/前端侧 |
| `src-tauri/Cargo.toml` | `[package] version` | Rust 权威（`env!("CARGO_PKG_VERSION")` 读它） |
| `src-tauri/Cargo.lock` | 本工作区包 `snoop` 的 `version` | `cargo --locked` 要求和 Cargo.toml 一致 |
| `src-tauri/tauri.conf.json` | `"version"` | 打包元数据 |
| `latest.json` | `"version"` + `platforms.*.url` 里的文件名 | 远端更新清单 |

手工改容易漏，一律走脚本：

```bash
npm run bump 0.1.2                    # 指定版本号
npm run bump patch                    # 自动 +patch（0.1.1 → 0.1.2）
npm run bump minor                    # 自动 +minor（0.1.1 → 0.2.0）
npm run bump 0.1.2 --notes "修复 X"    # 顺便更新 latest.json 的 notes 字段
```

脚本行为：
- 各文件的 version 字段一次性替换到目标版本
- `Cargo.toml` 只匹配文件顶部 `[package]` 段的 version 行，不误伤依赖版本
- `Cargo.lock` 只改 `[[package]] name = "snoop"` 条目，保证 `--locked` 构建能过
- `latest.json` 里 `platforms.*.url`（如 `Snoop_0.1.1_x64-setup.exe`）会同步换新版本号
- `latest.json` 里所有平台的 `sha256` 会被**清空**，因为新 installer 还没构建，必须 build 完手工回填正确 hash（避免旧 hash 骗过校验）

改完先 `git commit`，出问题好回退。

## 2. 构建

**Windows（在 Windows 上跑）：**
```bash
npm ci
npm run tauri build
```
产物：
```
src-tauri/target/release/bundle/nsis/Snoop_<版本>_x64-setup.exe
```

**macOS（在 Mac 上跑）：**

只出当前架构：
```bash
npm ci
npm run tauri build
```
产物：
```
src-tauri/target/release/bundle/dmg/Snoop_<版本>_<arch>.dmg
```

要同时出两个架构：
```bash
npm run tauri build -- --target x86_64-apple-darwin
npm run tauri build -- --target aarch64-apple-darwin
```
产物分别在 `src-tauri/target/{x86_64|aarch64}-apple-darwin/release/bundle/dmg/`。

**跨平台构建不做**：Windows 上不出 Mac 包，反之亦然。CI 一般也是各起各的 runner。

## 3. 校验产物 + 回填 SHA256

**统一走一个命令**，别再手抠 hash 了：

```bash
npm run verify-release           # 缺产物就报错;sha256 空的会回填,已填的会核对
npm run verify-release -- --check  # 只校验不改文件,CI/dry-run 用
```

脚本会读 `latest.json` 里每个平台条目,拿 `url` 里的文件名去 `src-tauri/target/**/bundle/{dmg,nsis}/` 找本地产物：

- **找不到** → 报错并列出查找过的路径。Mac 侧最容易忘的就是漏出一个架构的 dmg。
- **找到但 latest.json 里 sha256 为空** → 算完自动回填。
- **找到且 sha256 已填但对不上** → 报错。通常是文件被换过或者 latest.json 陈旧,别硬发。

Mac 的 dmg 客户端更新器**当前不校验 sha256**（走手动下载分支），但这里照样算并写进 latest.json，用来在上传前把"latest.json 说的这个文件"和"我要传的这个文件"绑定住 —— 不然只改了 URL 里的版本号,包却漏 build 的 bug 完全没人挡。

**手动兜底**（脚本坏了才用）：
```bash
shasum -a 256 Snoop_0.1.1_x64.dmg | awk '{print tolower($1)}'
```
Windows PowerShell：
```powershell
certutil -hashfile "Snoop_0.1.1_x64-setup.exe" SHA256
```

## 4. 上传到雨云

**要上传的东西：**
- `Snoop_<版本>_x64-setup.exe`（Windows）
- `Snoop_<版本>_x64.dmg`（Mac Intel，可选）
- `Snoop_<版本>_aarch64.dmg`（Mac Apple Silicon，可选）
- `latest.json`（覆盖上一版的）

**建议顺序：先传 installer，再传 `latest.json`。** 反过来会有一小段时间：客户端读到新版本号，但去下 installer 时 404，进入 `error` 状态。

**建议开 CDN 缓存但对 `latest.json` 设短 TTL**（60 秒左右），installer 可长缓存。

## 5. latest.json 模板

上传到 `https://snoop.cn-nb1.rains3.com/latest.json`：

```json
{
  "version": "0.1.1",
  "notes": "简短的版本说明,目前只作留档,前端不显示",
  "platforms": {
    "windows-x86_64": {
      "url": "Snoop_0.1.1_x64-setup.exe",
      "sha256": "小写hex的sha256"
    },
    "darwin-x86_64": {
      "url": "Snoop_0.1.1_x64.dmg",
      "sha256": ""
    },
    "darwin-aarch64": {
      "url": "Snoop_0.1.1_aarch64.dmg",
      "sha256": ""
    }
  }
}
```

**字段说明：**
- `version`：纯 `major.minor.patch`，别加 `v` 前缀
- `url`：相对 base URL 的路径，或完整 URL 都行
- `sha256`：Windows 必填、小写 hex；Mac 填空字符串即可（不校验下载）
- Mac 出 universal dmg 的话，两个 darwin key 都指向同一个 URL；只出一种架构时，另一个 darwin key 留**空条目**（`version` / `url` / `sha256` 都是空串），客户端会判定「已是最新」

**不要直接删掉某个 darwin key**：`updater.rs` 找不到 `platforms[key]` 会报 `latest.json 缺少当前平台条目`，用户看到的是「检查失败」。不出包的架构要保留空条目，`scripts/make-release-manifest.mjs` 会自动补。

## 6. 客户端会怎么走

**Windows：**
1. 启动 3 秒后后台请求 `latest.json`
2. 版本比自己新 → 1 MB/s 限速下载 exe 到 `%APPDATA%/org.feedra.snoop/updates/pending.exe`
3. SHA256 校验通过 → 写 `pending_update.json`,托盘菜单顶部出现「有新版本待安装 · 点击重启安装」
4. 用户点托盘那条,或者下次启动应用时,启动逻辑发现 pending → `installer.exe /S` 静默装 → 当前进程 exit
5. 装完 NSIS 会自动拉起新版应用

**macOS：**
1. 启动 3 秒后后台请求 `latest.json`
2. 版本比自己新 → 进 `manual_download` 状态,前端设置页按钮切成「打开下载页」,托盘菜单出现「有新版本可下载 · 点击打开下载页」
3. 用户点按钮 → `opener.open_url` 打开雨云上的 dmg 直链
4. 用户手拖 .app 到 Applications 完成

任何一步失败都 `error`,前端设置页可以看到错误消息;后台失败会被静默吞掉不打扰用户。

## 7. 测试完整更新链路

因为源码里的 `CARGO_PKG_VERSION` 就是当前版本,直接 `npm run tauri dev` 会认自己是最新,看不到更新流程。要真正验证得走这个流程：

**Windows 完整测试：**

1. 把三处版本号临时改成一个「旧版本」,比如 `0.1.0`：
   ```
   package.json / Cargo.toml / tauri.conf.json → "0.1.0"
   ```
2. `npm run tauri build` 得到 `Snoop_0.1.0_x64-setup.exe`
3. 双击安装,启动应用
4. 退出应用(托盘右键 → 退出,不能只关窗口)
5. 把三处版本号改回真实新版本 `0.1.1`,`npm run tauri build`
6. 把 `Snoop_0.1.1_x64-setup.exe` 和更新过 hash 的 `latest.json` 上传到雨云
7. 再启动第 3 步装的旧版应用,打开设置页,观察「检查更新」这一行：
   - 3 秒内应该进 `checking`
   - 然后 `downloading` 带百分比
   - 完成后按钮变主色「重启安装」,托盘也多出对应菜单项
8. 点「重启安装」或退出重开应用,应该无感换成 0.1.1

**如果卡住看哪里：**
- 应用日志:控制台输出的 `[updater] ...` 行
- pending 状态:`%APPDATA%/org.feedra.snoop/updates/pending_update.json`
- 下载文件:`%APPDATA%/org.feedra.snoop/updates/pending.exe`
- 强制重来:删掉整个 `updates/` 目录再启动

## 8. 回滚

如果新版本发出去发现有大问题,想让所有客户端回到旧版：

**不能真的让客户端自动降级**（自更新只做 `>` 比较,不装比自己旧的包）。能做的是**让「检查更新」这一步停止推送新版本**：

1. 把 `latest.json` 里的 `version` 改回上一个稳定版号
2. `url` 指向那个旧 installer(需要还留在 bucket 里)

这样新装的用户装到稳定版,已经装到问题版本的用户需要手动降级(卸载 + 重装旧 installer)。

**教训**：出重要版本前多做一轮本地测试,不出现「必须回滚」的场面。旧 installer 一年内不要从 bucket 删,给回滚留退路。

## 9. 已知限制

- **没做签名校验**:客户端只验 HTTPS + SHA256。如果雨云 bucket 被入侵,攻击者能同时改 installer + `latest.json` 里的 sha256,客户端认不出来。将来要加 ed25519 签名再叠一层。
- **Windows 没做 code signing**:装包时 SmartScreen 会拦一下,用户需要点「仍要运行」。有钱可以买 EV 代码签名证书。
- **Mac 没做 codesign / notarize**:Gatekeeper 会拦,用户首次运行需要在系统偏好设置里放行。因此 Mac 走「手动下载」而不是自动安装。
- **Linux 不支持自更新**:客户端会返回 `latest.json 缺少当前平台 unsupported 的更新条目` 的 error。目前 Linux 不是发布目标,忽略。

## 11. Windows 全局键鼠监听：Raw Input（不是 rdev）

Windows 下 Snoop **不用** rdev 的 low-level hook（`WH_KEYBOARD_LL` / `WH_MOUSE_LL`），改走 Raw Input API（`WM_INPUT`）。原因和影响直接看代码 `src-tauri/src/raw_input_windows.rs` 的开头注释，本节只讲跟打包/合规相关的部分。

**为什么切**：EAC、小蓝熊、Wallpaper Engine 等反外挂/防宏工具会主动拦截或反注册其它进程的 low-level hook，一旦发生 `rdev::listen` 会静默返回，Snoop 从此收不到任何全局键鼠事件，键鼠计数直接归零。Raw Input 走的是内核层原始设备通道（游戏本身用它），不经过 hook 链，反外挂工具挡不住。

**跟反外挂的兼容性**：Raw Input 是**纯读**的被动订阅（`RegisterRawInputDevices` + `RIDEV_INPUTSINK`），没有任何 `SendInput` / `keybd_event` / `PostMessage` / hook 注入。不读游戏内存、不注入 DLL、不 hook 游戏 API。行为跟"游戏自己收键盘"完全同源，VAC/EAC/Vanguard 拦不到也不该拦。

**打包依赖**：`src-tauri/Cargo.toml` 里 `windows` crate 需要开这三个 feature，构建脚本自动带：
```
Win32_UI_Input
Win32_UI_Input_KeyboardAndMouse
Win32_System_LibraryLoader
```

**非 Windows 平台**（macOS / Linux）**继续用 rdev**，`activity_tracker.rs` 里通过 `#[cfg(target_os = "windows")]` 分支切换调用点。因此这个改动对 macOS 打包流程零影响。

## 10. 发布 checklist（复制到 commit message 里核对）

```
[ ] npm run bump <版本> 一次同步版本号（package.json / Cargo.toml / Cargo.lock / tauri.conf.json / latest.json）
[ ] git commit 版本号变更
[ ] Windows: npm run tauri build 成功
[ ] Mac(可选): npm run tauri build 成功（两个架构分别跑一次 --target）
[ ] npm run verify-release 通过（自动核对本地产物 + 回填 sha256）
[ ] installer / dmg 已上传到雨云
[ ] latest.json 已上传到雨云（最后一步）
[ ] 用旧版应用手动测过更新链路
[ ] 打 tag: git tag v<版本> && git push --tags
```

## 12. CD：GitHub Actions 自动发版

工作流文件 `.github/workflows/release.yml`，解决的就是上面 checklist 里从「bump」到「上传 latest.json + 打 tag」这一段。**只需要在 GitHub 上填版本号和更新说明，其余全自动**。

### 一次性配置

Settings → Secrets and variables → Actions：

| 类型 | 名称 | 值 |
| --- | --- | --- |
| Secret | `AWS_ACCESS_KEY_ID` | 雨云 S3 的 Access Key |
| Secret | `AWS_SECRET_ACCESS_KEY` | 雨云 S3 的 Secret Key |
| Secret | `S3_ENDPOINT` | 区域端点，如 `https://cn-nb1.rains3.com` |
| Secret | `S3_BUCKET` | 存储桶名，如 `snoop` |
| Variable（可选） | `S3_REGION` | 默认 `us-east-1`；签名报 region 错误时填控制台显示的区域 |
| Variable（可选） | `S3_ADDRESSING_STYLE` | 默认 `virtual`；报域名/桶名拼接错误时改 `path` |

- **`S3_ENDPOINT` 填区域端点，不要填 `https://snoop.cn-nb1.rains3.com`**。aws-cli 用 virtual-host 方式拼成 `桶名.端点`，正好就是客户端写死的 `snoop.cn-nb1.rains3.com`。填成桶域名会变成 `snoop.snoop...`。
- AK/SK 只能进 Secrets，不要写进仓库、issue 或日志。

### 怎么发一版

Actions → Release → Run workflow：

| 输入 | 说明 |
| --- | --- |
| `version` | `x.y.z`，不带 `v`；必须大于 `main` 上的当前版本 |
| `notes` | 更新说明，写进 `latest.json` 和 GitHub Release，可留空 |
| `dry_run` | 勾上只构建 + 生成清单，不传 S3、不提交、不发 Release（第一次建议先跑一遍） |

> **不要先手动 `npm run bump`**：工作流会自己 bump、提交并打 tag。你只需要确认要发的代码已经在 `main` 上、CI 是绿的。

也可以命令行触发：

```bash
gh workflow run release.yml -f version=0.2.4 -f notes="修复报告灯箱缩放"
```

### 流水线做的事

1. **校验**：版本号格式、必须大于当前版本、`v<版本>` tag 不能已存在（重跑除外）、正式发版必须在 `main` 上。
2. **并行构建**（都不签名）：
   - macOS `macos-15`：只加 `aarch64-apple-darwin` target，`tauri build --target aarch64-apple-darwin`，出 Apple Silicon 的 dmg（文件名 `Snoop_<版本>_aarch64.dmg`，官网下载链路依赖这个命名）。先不出 Intel 包：universal 体积翻倍，US runner 跨洋传雨云太慢。
   - Windows `windows-2022`：`tauri build`，出 NSIS 安装包。
   - 两个 job 都在本地执行 `npm run bump`，只改工作区文件，不提交。
3. **生成清单**：`scripts/make-release-manifest.mjs` 对实际产物算 SHA256，写 `latest.json`。aarch64 dmg 映射到 `darwin-aarch64`，`darwin-x86_64` 写空条目（Intel 客户端判定「已是最新」）；Windows 映射到 `windows-x86_64`。字段（`version` / `notes` / `platforms.*.url` / `sha256`）和相对 URL 解析方式都对齐 `src-tauri/src/updater.rs`，不是 Tauri 官方 updater 的清单格式。
4. **上传 installer**：dmg / exe 先传，文件名带版本号，不覆盖旧包。
5. **留痕**：把版本号变更提交成 `chore(release): 发布 v<版本>` 推到 `main`，打 annotated tag `v<版本>`。
6. **最后上传 `latest.json`**：这是客户端的“上线开关”。它落桶之前，所有客户端仍看到旧版本；落桶之后，新包一定已经在桶里。
7. **回读校验**：把 `latest.json` 从 S3 拉回来逐字节比对，并用 `head-object` 核对两个 installer 的大小。
8. **GitHub Release**：创建 release，附件含 dmg / exe / latest.json。

### 失败窗口

| 失败位置 | 线上状态 | 恢复 |
| --- | --- | --- |
| installer 上传 | 清单未换，客户端无感 | 重跑 |
| 提交 / tag | 清单未换，客户端无感 | 重跑（tag 若已存在会跳过提交） |
| `latest.json` 上传 | 清单未换，客户端无感 | 重跑（tag 存在，跳过提交） |
| 回读校验 | 清单可能已换，但内容不一致会显式报错 | 重跑 |
| GitHub Release | 更新已上线，只是缺 Release 页面 | 重跑（补建 Release） |

### 重跑与失败处理

- 构建失败：直接 Re-run failed jobs，会重新构建。
- **重跑已有版本时，构建 job 先 fetch 并 checkout `v<版本>` tag**，用当时的源码构建，保证同一个版本号不会发出两份不同的代码。
- 版本号已提交、tag 已打，但上传或 Release 失败：重跑时 `tag_exists=true`，跳过提交和打 tag，只重新上传并补建 Release。
- 只允许重跑**最新版本**。旧版本 tag 存在时，准备 job 会直接报错，避免把线上 `latest.json` 回滚。
- `main` 如果有分支保护，`GITHUB_TOKEN` 推不上去，需要换 PAT 或放开 Actions 的推送权限。

### 注意

- 两边都**没签名**：macOS 首次打开仍要在「系统设置 → 隐私与安全性」里放行，Windows 仍会弹 SmartScreen。这和手动打包的产物一致，不是 CD 引入的问题。
- CD 只在 `main` 上发版（dry_run 除外）。发版前先确保 CI 的 `CI` 工作流是绿的。
- 旧的 installer 文件名自带版本号，不会被覆盖；不要从桶里删，回滚用得上（见第 8 节）。
